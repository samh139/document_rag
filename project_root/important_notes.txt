Vector Database-
Traditional databases store the data in rows and columns similar to excel format
Vector databases store the  embeddings which are long lists of numbers that represent the meaning of data
Why would be store the meaning as numbers - Think of a room full of floating balloons.. each balloon represents a piece of information, similar balloon floats together.. eg Sports, Fitness cluster in together..
Where do embeddings come from - embeddings are like gps co-ordinates of balloons in that room.. it tells you where that piece of information lives
How does it differ from normal search - Unlike normal search..u are not asking to match exact label.. In vector search.. u are asking show me the ballots near this one.. so even if words are different, the meaning pulls them together..
How does it search fast with millions of vectors - It uses something called Approximate Nearest Neighbour Search.. instead of checking into every vector, it zooms into right cluster 

Agglomerative distance refers to the method of calculating similarity between clusters in agglomerative hierarchical clustering, a "bottom-up" approach 
where each point starts as a cluster, and pairs are merged based on how "close" they are, using different linkage criteria like single (closest points),
 complete (furthest points), or average distance, until all points form one big cluster.


 Retrieval using Clusters-
 6️⃣ Why two levels?

Because retrieval is hierarchical.

Level-1 (Root cluster) → coarse routing

Question:

“Which broad topic does this query belong to?”

You compare:

query_vector  vs  all root cluster vectors


You select top-K root clusters.

This is:

Very fast (few clusters)

Very coarse (big semantic buckets)

Level-2 (Subclusters) → fine routing

Inside selected root clusters, you compare:

query_vector vs subcluster vectors


Now you select:

2–5 subclusters per root cluster

This narrows the search to hundreds instead of thousands of chunks.

Without clusters

BM25 over 100k chunks

Vector search over 100k vectors

RRF merges garbage + signal

With clusters

BM25 over maybe 2–3k chunks

Vector search over same subset

RRF becomes sharp and stable

Level 1

Root clusters

Each has:

vector → centroid of many chunks

Represents a coarse topic region

Level 2

Subclusters

Each has:

vector → KMeans center

Represents a fine-grained semantic pocket
